# Diagram sandbox

Runs model-generated interactive diagrams ("explorables") in
`<iframe sandbox="allow-scripts" src="mint-sandbox://app/index.html">`.

| File | Role |
| --- | --- |
| `index.html` | Sandbox page. Strict CSP (also sent as a header by `src/main/diagramProtocol.ts`). |
| `runtime.js` | Protocol endpoint, the `mint` API, hit-testing, highlight overlay, teardown. |
| `geometry.js` | Pure hit-testing/coordinate helpers (`MintGeometry`), unit-tested in `tests/unit/diagramGeometry.test.ts`. |
| `sandbox.css` | Page layout. |
| `vendor/` | Generated by `npm run prepare-runtimes` (`scripts/build-diagram-runtime.mjs`): `p5.min.js` (p5 1.11), `three.iife.js` (three r187 + `OrbitControls`). Git-ignored. |

Security model: opaque origin (no `allow-same-origin`), no Node, CSP
`default-src 'none'` / `connect-src 'none'` (no fetch, XHR, WebSocket, fonts,
remote images, frames or workers), WebRTC constructors removed, and the main
process blocks sandbox frames from navigating off `mint-sandbox://app/`. The
host accepts only messages from the iframe's own window that pass
`isSandboxMessage` (`src/shared/diagramProtocol.ts`).

## Sketch contract

A diagram is a `DiagramSpec` (`src/shared/types.ts`):
`{ engine: 'p5' | 'three', title, code, elements: [{id, label, description}], params: [{id, label, min, max, step, value}], caption }`.

`code` is plain browser JavaScript (ES2022). Rules:

1. **No network, no assets.** `fetch`, `loadImage(url)`, `loadFont`, `loadJSON`, external scripts, `import` and
   WebSockets all fail. Draw everything procedurally. `data:` image URLs are allowed.
2. **Draw into `mint.stage`.** The stage fills the iframe; its size is `mint.width` x `mint.height` (CSS px).
3. **Every element id in `spec.elements` should be registered** every time it is drawn (`mint.region` for p5,
   `mint.object` for three) so the learner can click it and the tutor can highlight it. Ids are non-empty
   strings of at most 200 characters. The label shown to the learner comes from `spec.elements`.
4. **Every interactive quantity is a `spec.params` entry** read via `mint.param(id)`; do not build DOM sliders —
   the host renders them.
5. Do not implement highlight visuals yourself: the runtime draws them. `mint.isHighlighted` /
   `mint.onHighlight` are only for extra, sketch-specific emphasis.
6. Code runs inside a function scope: top-level `let`/`const`/`function` are private to the sketch. In p5
   global mode the hooks (`setup`, `draw`, `mousePressed`, …) are exported automatically.
7. Uncaught errors are reported to the tutor with the sketch line number. A sketch that shows no canvas
   within 3 s is reported as "The diagram did not draw anything".

### `mint` API

| Member | Description |
| --- | --- |
| `mint.param(id) → number` | Current value of a `spec.params` entry (starts at its `value`; host changes are clamped to `[min, max]`). Unknown id → `0` plus a console warning. |
| `mint.onParam((id, value) => void) → unsubscribe` | Called whenever a param changes (host slider or `mint.setParam`). Not called for the initial values. |
| `mint.setParam(id, value)` | Set a param from sketch code (e.g. dragging a handle). Clamped to `[min, max]`; the host slider follows. |
| `mint.region(id, shape)` | **p5.** Register/update the clickable area of an element, in p5 canvas coordinates (the same units as `width`/`height`, origin top-left; in `WEBGL` mode add `width/2`, `height/2` to centred coordinates). Call it in `draw()` right where the element is drawn; the latest shape per id wins, and the most recently registered region is on top for overlapping clicks. Shapes: `{circle: [x, y, r]}`, `{rect: [x, y, w, h]}`, `{segment: [x1, y1, x2, y2], width: strokeWidth}`, `{polygon: [[x, y], [x, y], [x, y], ...]}`. Every shape is clickable within 4 CSS px of its edge; segments within `width / 2 + 4px`. |
| `mint.object(id, object3D)` | **three.** Register a `THREE.Object3D` (mesh, group, line, points…) as element `id`. Clicks on any descendant resolve to the nearest registered ancestor; the closest hit wins. |
| `mint.useCamera(camera, renderer)` | **three, required for clicks.** The camera and `THREE.WebGLRenderer` to raycast with. The runtime also keeps this renderer sized to the stage and updates a `PerspectiveCamera`'s aspect on resize. |
| `mint.isHighlighted(id) → boolean` | Whether the tutor currently highlights `id`. |
| `mint.onHighlight((ids) => void) → unsubscribe` | Called with the full list of highlighted ids whenever it changes. |
| `mint.onResize((width, height) => void) → unsubscribe` | Called when the stage size changes. |
| `mint.width`, `mint.height` | Stage size in CSS px. |
| `mint.stage` | The container element (`HTMLDivElement`). |

### p5 (`engine: 'p5'`)

p5.js **1.11** (not 2.x). Global mode (top-level `function setup()` / `function draw()`) or instance mode
(`new p5((p) => { … }, mint.stage)`); never call `new p5()` in global mode — the runtime starts it. The canvas is
placed in the stage and centred. A `createCanvas` larger than the stage is scaled down to fit (CSS only:
`mouseX`/`mouseY`, regions and highlights stay in canvas coordinates). Prefer
`createCanvas(mint.width, mint.height)` and, for responsive sketches,
`function windowResized() { resizeCanvas(mint.width, mint.height) }`.

```js
// Pendulum: params [{id:'length', min:50, max:250, step:1, value:150}, {id:'angle', min:-60, max:60, step:1, value:30}]
// elements [{id:'pivot'}, {id:'rod'}, {id:'bob'}]
function setup() {
  createCanvas(mint.width, mint.height)
}

function draw() {
  background(250)
  const px = width / 2, py = 40
  const a = radians(mint.param('angle'))
  const bx = px + mint.param('length') * sin(a)
  const by = py + mint.param('length') * cos(a)

  stroke(60); strokeWeight(3)
  line(px, py, bx, by)
  mint.region('rod', { segment: [px, py, bx, by], width: 3 })

  noStroke(); fill(60)
  circle(px, py, 10)
  mint.region('pivot', { circle: [px, py, 5] })

  fill(mint.isHighlighted('bob') ? '#f5a524' : '#3a6ea5')
  circle(bx, by, 36)
  mint.region('bob', { circle: [bx, by, 18] })
}

function windowResized() {
  resizeCanvas(mint.width, mint.height)
}
```

### three (`engine: 'three'`)

three.js **r187** as the global `THREE` (no imports), with `THREE.OrbitControls`. Append
`renderer.domElement` to `mint.stage`, call `mint.useCamera(camera, renderer)`, register elements with
`mint.object`. Animate with `renderer.setAnimationLoop` or `requestAnimationFrame`; a scene rendered only once
is fine too (the runtime re-renders it when highlights change or the stage resizes). Everything is disposed
automatically when the next diagram loads.

```js
// params [{id:'tilt', min:0, max:90, step:1, value:23}]; elements [{id:'planet'}, {id:'axis'}]
const scene = new THREE.Scene()
const camera = new THREE.PerspectiveCamera(45, mint.width / mint.height, 0.1, 100)
camera.position.set(0, 1.5, 5)
const renderer = new THREE.WebGLRenderer({ antialias: true })
renderer.setPixelRatio(devicePixelRatio)
renderer.setSize(mint.width, mint.height)
mint.stage.appendChild(renderer.domElement)
mint.useCamera(camera, renderer)
const controls = new THREE.OrbitControls(camera, renderer.domElement)

scene.add(new THREE.AmbientLight(0xffffff, 0.6))
const sun = new THREE.DirectionalLight(0xffffff, 2)
sun.position.set(5, 3, 5)
scene.add(sun)

const planet = new THREE.Group()
const globe = new THREE.Mesh(new THREE.SphereGeometry(1, 48, 32), new THREE.MeshStandardMaterial({ color: 0x3a6ea5 }))
const axis = new THREE.Mesh(new THREE.CylinderGeometry(0.03, 0.03, 3), new THREE.MeshStandardMaterial({ color: 0xdddddd }))
planet.add(globe, axis)
scene.add(planet)
mint.object('planet', globe)
mint.object('axis', axis)

renderer.setAnimationLoop(() => {
  planet.rotation.z = THREE.MathUtils.degToRad(mint.param('tilt'))
  globe.rotation.y += 0.005
  controls.update()
  renderer.render(scene, camera)
})
```
